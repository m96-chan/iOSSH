# iOSSH

[English](README.md) | 日本語

> 余計な機能を足さない、iOS 向け SSH クライアント。

ターミナルとして正しく動くこと、速いこと、それ以外を持ち込まないこと。
Kitty Graphics Protocol による画像表示と、Metal による GPU レンダリングを前提に設計する。

> **Status: 初期実装済み — v1 の受け入れ検証は継続中。**
> 以下の番号付きセクションは目標とする設計。現在の実装と差分をここに記載する。

iPhone / iPad アプリとして、SwiftData のホスト管理、Keychain の資格情報保存、SSH の PTY セッション、初回ホスト鍵の明示的な承認、再接続、Metal ターミナルを実装。VT 処理には設計上の退避先である **SwiftTerm** を `TerminalEngine` 越しに使用し、libghostty-vt バイナリは不要。

iPad ビルドには専用の [iPad ワークスペース](#ipad-ui) を実装。横幅に適応するホストサイドバー、接続を保持する最大 4 タブ、狭いウィンドウでのセッションメニューを備える。iPhone は単一セッションの接続フローを維持する。iPad 実機での受け入れ確認と連続出力の計測は今後行う。

認証はパスワード、OpenSSH 形式の Ed25519 鍵（対応する暗号化鍵を含む）、暗号化されていない ECDSA PEM 鍵、接続済みの Tailscale アプリを利用する Tailscale SSH に対応。**Tailscale SSH** を選ぶと、パスワードや鍵を入力せず端末名で接続でき、サーバーが check mode の承認を要求した場合はサインイン用リンクを表示する。現在の SSH 依存ライブラリには keyboard-interactive の実装がなく、RSA も未対応のため、アプリでは選択できない。

CoreText のグリフアトラス、Metal のインスタンス描画、24bit 色、キーボード操作・補助キー、選択・コピー・ペースト、scrollback、ダーク / ライトテーマを実装。Kitty の direct RGB / RGBA / PNG 転送には保存容量の上限を設けている。画像アニメーション、圧縮転送、相対配置、明示的な画像クロップは未対応。リサイズ時は通常の画像配置を破棄するが、Unicode placeholder の配置はテキストに追従して reflow 後も保持する。

日本語と Starship / Nerd Font の記号に対応する HackGen Console NF を標準同梱し、初期サイズは 9pt とする。未収録の日本語文字は、追加したフォントを使う場合も含め、同梱の Noto Sans CJK JP で補う。設定から「ファイル」の等幅 TTF / OTF フォントを追加し、iOSSH 内で選択できる。グリフを端末のセル幅に収め、アプリ復帰・再接続時もキーボードと補助キー行に合わせて表示領域を更新する。日本語入力には UIKit の変換機能を使い、確定した文字だけを送信する。

VT パースは現時点では `MainActor` 上で行う。専用 actor への移行、libghostty-vt バックエンド、Display P3 出力、実機での 120Hz・消費電力計測は今後の作業。画面ロック・バックグラウンド移行時は SSH 接続と端末の内容を保持する。復帰時に既存接続を確認し、生きていれば同じシェルへ復帰する。切断後の再接続は新しいシェルを開く。接続が切れた後もシェルを継続したい場合は、接続先でマルチプレクサを利用する。

ビルド手順、対応する鍵形式、テスト内容は [開発・検証ノート](docs/DEVELOPMENT.jp.md) を参照。

## 1. 設計方針

| 柱 | 意味 |
| --- | --- |
| **Simple** | 機能を足さないことを設計判断の第一基準にする。「あると便利」は入れない |
| **Correct** | VT / Unicode / Kitty の挙動がデスクトップの端末と一致すること。幅計算・reflow・色で嘘をつかない |
| **Fast** | GPU レンダリングで ProMotion 120Hz を維持し、入力から描画までのレイテンシを最小にする |

対象は **iPhone / iPad 両方**、**iOS / iPadOS 17+**（Metal 3・Swift 6 strict concurrency を前提にするため）。iPhone では小さな画面で 1 本のターミナルを使うことを優先し、iPad では大きなターミナルの周囲に接続先の選択とセッション切り替えを配置する。iPad のマルチタスクやウィンドウのリサイズを含め、実際に使える横幅に応じてレイアウトを変える。

## 2. スコープ

### v1 でやること

- ホスト一覧の登録・編集
- 認証: パスワード / 公開鍵 / keyboard-interactive
- 資格情報を Keychain に保存、Face ID / Touch ID で保護
- ホスト鍵検証（TOFU + `known_hosts` 相当の永続化、変更時は警告）
- **PTY セッションとウィンドウサイズ追従**: iPhone は 1 セッション、iPad は独立した接続タブを持ち、同時に表示するターミナルは 1 つ
- **iPad 専用 UI**: 折りたためるホストサイドバー、標準で有効な接続タブ、狭いウィンドウでのセッション選択メニュー
- **24bit True Color / 256 色 / ANSI 16 色**
- **Kitty Graphics Protocol による画像表示**
- ハードウェアキーボード、トラックパッド、ポインタ対応（iPad / Magic Keyboard）
- ソフトウェアキーボード上の補助キーバー（Ctrl / Esc / Tab / 矢印 / `|` / `~`）
- コピー & ペースト、テキスト選択
- フォントの選択・追加、フォントサイズ・カラーテーマ設定
- 切断検知と再接続

### v1 でやらないこと（意図的に落とす）

| 機能 | 落とす理由 |
| --- | --- |
| SFTP / ファイル転送 | 別アプリの領分。UI が一気に膨らむ |
| ポートフォワーディング | 常時接続が前提の機能で、iOS のバックグラウンド制限と相性が悪い |
| mosh | サーバ側に別バイナリを要求する。再接続 UX で代替する |
| tmux control mode | ネイティブ UI との統合は v1 の複雑度を超える |
| ターミナルのペイン分割 | 表示するターミナルを 1 つにして入力先と表示領域を明確にする。iPad のセッション切り替えには接続タブを使う |
| アプリの複数ウィンドウ | 最初の iPad ワークスペースは 1 つのアプリウィンドウでセッションを保持する。ウィンドウ間の所有関係は将来別途設計する |
| エージェントフォワーディング | セキュリティ上の判断が必要で、v1 の検証範囲に収まらない |
| Sixel / iTerm2 画像プロトコル | 画像プロトコルは Kitty に一本化する |
| iCloud 同期 | 秘密鍵の同期は設計を慎重にやる必要があり、v1 では持たない |

これらは「将来やらない」ではなく「v1 に入れない」。追加するときは、この表から 1 行削るという意思決定を経る。

### iPad UI

iPad では、外付けキーボードで接続先のファイルを編集し、ログを追い、複数のマシンを行き来する使い方を想定する。接続タブは **iPad で標準 ON** とする。各タブは独立した SSH シェルを持ち、ターミナルのペイン分割は今回の対象に含めない。

#### レイアウト

| 利用状況 | ナビゲーション | ターミナル領域 |
| --- | --- | --- |
| iPhone | ホスト一覧から現在の単一セッション画面へ進む | 画面を使う 1 つのターミナル。常設タブ列は置かない |
| 十分な横幅のある iPad ウィンドウ | 折りたためるホストサイドバーと、ターミナル上部の接続タブ | サイドバーの隣に大きなターミナルを表示。サイドバーを隠すと広がる |
| 狭い iPad ウィンドウ | サイドバーとタブ列を畳み、ツールバーからホストとセッションを選ぶ | 選択中のターミナルが横幅を使う。開いている全セッションを保持する |

詳細領域の最上部 1 行に、サイドバーの表示切り替え、接続タブ、セッション操作をまとめる。接続先を中央に表示する別のタイトル行は置かず、ソフトウェアキーボード表示中のターミナルの高さを確保する。設定はサイドバー下部に置き、狭い表示では **Hosts** 選択画面から開く。ターミナルは角丸とし、小さな内側余白で文字が縁にかからないようにする。

```text
+------------------+-----------------------------------------------+
| iOSSH       [+]  | [dev *] [logs] [staging] [+]                  |
+------------------+-----------------------------------------------+
| Hosts            |                                               |
|   Development    | user@dev:~$                                   |
|   Logs           |                 Active terminal               |
|   Staging        |                                               |
|                  |                                               |
| Settings         |                                               |
+------------------+-----------------------------------------------+
| Ctrl  Esc  Tab  arrows  |  ~                      Hide keyboard  |
+------------------------------------------------------------------+
| Software keyboard, when shown                                    |
+------------------------------------------------------------------+
```

図は通常位置のソフトウェアキーボードを表示した展開時の配置で、`*` は選択中のタブを表す。サイドバーには保存済みホストと設定、詳細領域には接続タブとターミナルを置く。補助キー行はソフトウェアキーボードとともに表示する。操作部はシステムのセーフエリアとウィンドウ操作ボタンを避ける。Apple の[レイアウト指針](https://developer.apple.com/design/human-interface-guidelines/layout)と [NavigationSplitView の挙動](https://developer.apple.com/documentation/swiftui/navigationsplitview)を参考に、実際のウィンドウに適応するナビゲーションを使う。

#### ホストとタブの操作

- サイドバーのホストを選ぶとタブでシェルを開く。そのホストのタブが既にある場合は、直近に使ったものを選択する。同じホストへ別のシェルを開く場合は、ホストメニューの **New Session** を明示的に選ぶ。
- タブ列の `+` と `Command-T` は、**新規セッション用の接続先選択**を開く。ここからホストを選ぶと、既にそのホストのタブがあっても必ず新しいセッションを作る。保存済みホストの追加は、サイドバーの別操作として扱う。
- タブにはホスト名と接続状態（接続中、接続済み、接続確認中、操作待ち、切断済み）を表示する。同じホストへの複数接続には番号を付けて区別する。状態は色だけでなく、読み上げ可能なテキストでも伝える。
- タブを閉じる操作は、そのセッションだけを終了する。最後のタブを閉じるとホスト選択の空画面を表示する。切断済みタブには出力を残して **Reconnect** を表示し、再接続するとそのタブで新しい認証済みシェルを開く。
- タブが収まらない場合は横スクロールし、選択中のタブを見える位置に保つ。コンパクト表示のセッションメニューでも、同じタブ・状態・閉じる操作を使える。ウィンドウのリサイズで接続を閉じたり、別の接続に置き換えたりしない。
- 初期上限は、接続中・切断済みも含め **4 タブ** とする。上限時は既存タブを選ぶか、1 つ閉じてから追加するよう案内し、接続中のセッションを自動的に追い出さない。上限の見直しは実機のメモリと連続出力の計測後に行う。

#### キーボード・ポインタ・入力先

| ショートカット | ワークスペースの操作 |
| --- | --- |
| `Command-T` | 新しいセッションの接続先を選ぶ |
| `Command-W` | 選択中のセッションタブを閉じる |
| `Command-Shift-[` / `Command-Shift-]` | 前 / 次のセッションを選ぶ |
| `Command-1` … `Command-4` | タブの並び順でセッションを選ぶ |
| `Command-,` | 設定を開く |

使用できるショートカットはシステムのキーボードショートカット案内に表示する。`Ctrl-C`・`Ctrl-D`・`Ctrl-Z`、Option キーのシーケンス、ターミナルのコピー・ペーストは従来の動作を維持する。入力欄や表示中のシートでは通常の編集ショートカットを使い、ワークスペースの操作が入力を奪わないようにする。

文字入力、貼り付け、補助キー、日本語 IME の確定は選択中のターミナルだけへ送る。セッション切り替え時は未確定文字と一時的な修飾キー状態を取り消し、未確定文字をどちらのシェルにも送らない。選択画面やシートを閉じたら選択中のターミナルへ入力先を戻す。ポインタでは文字選択・コピー、履歴スクロール、ホストやタブのコンテキストメニューを利用できる。サイドバーとタブは Dynamic Type、VoiceOver、44 ポイント以上のタッチ領域に対応し、ターミナルは明示的に設定したフォントサイズを使う。

非同期の貼り付けは、開始時のセッション ID と接続試行を記録する。送信前に選択先や接続試行が変わった場合は未送信の内容を破棄し、再度貼り付けてもらう。新しく選択されたタブへ送り先を変更してはならない。

端末の最終行は不透明な補助キー行の上に置く。サイドバーの表示切り替え、画面回転、ウィンドウのリサイズ、通常・フローティング・外付けキーボードの切り替え後に、表示可能な行列数を再計算する。フローティングキーボードの高さを画面全体から差し引かず、実際の位置を避けて入力カーソルと日本語候補の基準位置を確保する。

#### 接続の寿命とリソース

- 保存済みホストの ID とは別に、実行中のセッションごとに安定した ID を付け、ワークスペースが所有する。タブ切り替え、ナビゲーションの折りたたみ、外観の変更、設定の表示では、各 SSH 接続・シェル・パーサの状態・履歴・カーソルを保持する。
- アプリのバックグラウンド移行・復帰は保持中の全セッションへ伝える。画面ロックから戻ったら既存接続を確認し、生きているシェルへ復帰する。プロセス終了や通信切断の後は新しい接続が必要で、タブの復元に伴って別のシェルを無断で開かない。
- 資格情報、ホスト鍵の承認、Tailscale サインインは選択中のセッションだけが表示する。他のタブは操作待ちの状態を示す。認証シートを同時表示せず、接続先を明記する。アプリ自身の確認画面には、要求を保持して他のタブを使う **Later** と、その接続試行を終了する **Cancel** を用意する。保留した確認画面は、そのタブの操作待ちボタンからだけ再表示し、非表示中も認証期限は進む。システムの生体認証ダイアログは OS の通常の挙動に従う。
- 認証の回答を要求元のセッション ID・接続試行・要求 ID に結び付け、キャンセル・タブ終了・再接続後の古いコールバックを無視する。表示を保留しただけで、現在の資格情報シートの「閉じるとキャンセル」という処理を実行してはならない。
- 非表示セッションでも出力の受信とパースを続ける。GPU 描画、カーソルのタイマー、高頻度のスナップショット生成を停止し、選択時に最新の画面を生成する。非表示中は最後の有効な PTY サイズを保持し、再表示時はキーボード入力を再開する前に、計測した表示領域のサイズを反映する。
- 描画リソースは表示中のターミナル分だけ保持し、非表示の GPU キャッシュを解放する。初期目標は **アプリ全体でデコード済み Kitty 画像 64 MiB**、既存の **1 画像 16 MiB** の上限、および上限付きの表示中グリフアトラスとする。各セッションの scrollback も上限を維持する。メモリ警告では画像・描画キャッシュを破棄できるが、SSH を自動切断したり端末のテキストを消したりしない。ワークスペース内の全セッションでこの上限を共有する。単独で生成した端末エンジンは自身の上限を持つ。

## 3. アーキテクチャ

図は 1 セッションの構成を表す。iPad ワークスペースでは、セッションストアが順序付きの `ConnectionModel` 群と選択中のセッション ID を持つ。各モデルが自身の `SSHSession` と `TerminalEngine` を保持し、選択中のモデルだけを表示中の `TerminalView` へ接続する。iPhone も同じ所有関係で 1 セッションを扱う。ビューが消えただけで接続を閉じてはならない。

```
        SwiftUI  (ホスト一覧 / 設定 / 接続フロー)
             │
      UIViewRepresentable
             ▼
   TerminalView (MTKView) ──► MetalRenderer ──┬──► GlyphAtlas  (MTLTexture)
             ▲                                └──► ImageStore  (Kitty graphics)
             │  grid snapshot + damage
             │
      TerminalEngine  (VT パース / グリッド / scrollback / Kitty 状態)
             ▲
             │  bytes
      SSHSession  (PTY channel, keepalive, 再接続)
             ▲
      Citadel / swift-nio-ssh
```

**`TerminalEngine` は protocol として定義する。** 実装（libghostty-vt バインディング）を差し替え可能にしておく。理由は [11. リスク](#11-既知のリスク--未決事項) を参照。

## 4. 技術選定

各レイヤについて「採用したもの」と「採用しなかったもの」を記録する。

| レイヤ | 採用 | 理由 | 却下した選択肢 |
| --- | --- | --- | --- |
| SSH | **[Citadel](https://github.com/orlandos-nl/Citadel)**（[apple/swift-nio-ssh](https://github.com/apple/swift-nio-ssh) の高レベルラッパ） | Pure Swift、SPM のみで完結、iOS を公式サポート。C ツールチェインのビルド管理が不要 | **libssh2 ラッパ（[SwiftSH](https://github.com/Frugghi/SwiftSH)）**: C 依存とクロスビルド管理のコスト。**NMSSH**: メンテナンス停滞。**swift-nio-ssh 直接**: クライアント実装を自前で組む必要があり、Citadel がやっていることを再発明する |
| VT エンジン | **[libghostty-vt](https://mitchellh.com/writing/libghostty-is-coming)**（Ghostty から切り出された C API） | **Kitty Graphics Protocol をエンジン側で実装済み**。SIMD パース、Unicode 幅計算、reflow、scrollback が実戦で枯れている。ゼロ依存（libc すら不要）で組み込みやすい | **自前 VT パーサ**: 工数が過大で、正しさの担保が最も難しい部分を自分で背負うことになる |
| VT エンジン（退避先） | **[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)** の `Terminal`（UI 非依存部分のみ） | libghostty-vt の API が未安定なため、protocol 越しに切り替えられる退避先を用意する。ただし Kitty Graphics は自前実装が必要になる | — |
| 描画 | **自前 Metal レンダラ**（`MTKView` + インスタンス描画） | CoreText 系は行ごとに `NSAttributedString` を再構築して描くため、セル数が多い・更新が速い状況で CPU バウンドになる。Kitty 画像もテキストと同じパイプラインでテクスチャ合成でき、z-index を素直に扱える | **CoreText 直描画**: 上記の通り CPU バウンド。**CALayer 合成**: セル単位のレイヤは数が多すぎる |
| グリフ | **CoreText で動的ラスタライズ → アトラステクスチャにキャッシュ** | 端末はセルサイズ固定で使用フォントサイズも少数。ヒント付きラスタの方が字が鮮明 | **MSDF**: スケールフリーという利点が端末では活きず、小さいサイズで品質が落ちる。アトラス生成の前処理も増える |
| UI | **SwiftUI（シェル）+ UIKit（ターミナル・キー入力）** | `MTKView` とキーイベント（`pressesBegan` / `UIKeyCommand` / `UIKeyInput`）は UIKit 側で扱うのが確実 | **全 SwiftUI**: 修飾キーや押下/離鍵の扱いで取りこぼしが出る |
| 永続化 | **Keychain（資格情報・秘密鍵）+ SwiftData（ホスト設定）** | 秘密情報と設定を物理的に分離する | 単一ストアにまとめる案 |
| 並行処理 | **Swift 6 strict concurrency**、エンジンは actor に隔離 | SSH 受信・VT パース・描画のスレッド境界を型で固定する | — |

## 5. GPU レンダリング設計

「GPU を使いたい」に対する具体的な方針。

### 描画トリガ

`MTKView.enableSetNeedsDisplay = true` の **damage 駆動**。毎フレーム回す方式は取らない。
アイドル時に GPU を焼かないことが、モバイルでは品質要件そのものになる。

### パス構成

1. **背景セル** — セル矩形をインスタンス描画（背景色のみ）
2. **グリフ** — アトラスの UV を参照してテキストを描く
3. **装飾** — 下線 / 二重下線 / 波線 / 取り消し線 / 罫線
4. **画像** — Kitty graphics のテクスチャを z-index 順に合成（テキストの前後どちらにも入りうる）
5. **カーソル** — ブロック / バー / アンダーライン、点滅

### バッファ戦略

- セルごとの instance buffer（cell index / atlas UV / fg・bg のパック色 / 属性ビット）
- `MTLBuffer` をトリプルバッファ化し、`DispatchSemaphore` で CPU と GPU の追い越しを制御
- エンジンの damage 情報を使い、**変更のあった行だけ** instance を書き換える

### 色

- 24bit True Color をそのまま扱う。256 色・ANSI 16 色はテーマのパレットから解決
- Display P3 / wide color に対応し、**ブレンドはリニア空間**で行う（アルファ合成の破綻を避ける）

### 電力・ライフサイクル

- バックグラウンド移行時に描画を停止する（バックグラウンドでの GPU 作業は許されない）
- ProMotion では `preferredFramesPerSecond` を上限に、実描画は damage 駆動のまま

## 6. Kitty Protocol 対応範囲

Kitty には目的の異なる仕様が複数ある。本プロジェクトでの扱いを明示する。

| 仕様 | 対応 | 範囲 |
| --- | --- | --- |
| **24bit True Color** | v1 必須 | `CSI 38;2;R;G;Bm` / `CSI 48;2;R;G;Bm`、256 色、ANSI 16 色。Kitty 固有ではないが「色が出る」のベースライン |
| **[Kitty Graphics Protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/)** | v1 | 下記参照 |
| **[Kitty Keyboard Protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)** | v1.1 | `CSI > u` / `CSI < u` / `CSI = u` によるプログレッシブ拡張、フラグのスタック push/pop。iPad + 外付けキーボードで Neovim / Helix を使うときに効く |

### Graphics Protocol の詳細

| 項目 | v1 の対応 |
| --- | --- |
| 転送方式 | **direct（base64 チャンク）のみ** — iOS ではファイル経由 / 共有メモリ転送が現実的でない |
| フォーマット | RGB / RGBA / PNG |
| 配置 | セルアンカー配置、`z` によるテキストとの前後関係、カラム/ロウオフセット、スケーリング |
| 削除 | `d` による各種削除コマンド |
| Unicode placeholder | 対応（Neovim の image プラグイン等が使う） |
| アニメーション | **v1 対象外** |

### `TERM` の扱い

Kitty 固有機能を要求されるため、対応が揃った時点で `TERM=xterm-kitty` を名乗る。
ただし接続先に `xterm-kitty` の terminfo が無いケースがあるため、**ホストごとに `TERM` を上書きできる設定**を持つ（既定は `xterm-256color`、Kitty 機能を使いたいホストで切り替える）。

## 9. 動作確認・受け入れ基準

「動いた」と言える条件を先に決めておく。

- **VT 互換性**: `vttest` の基本項目、`esctest` の主要スイートが通る
- **色**: `ls --color=always` / `htop` / `nvim` が実機と同じ色で出る。True Color のグラデーションに縞が出ない
- **Kitty 画像**: `kitten icat image.png`（または `timg -p kitty`）で画像が表示される / スクロールに追従する / 削除コマンドで消える / テキストとの前後関係が `z` の指定どおり
- **性能**: `yes` や大量ログの流し込み時にドロップフレームがない。実機で 120Hz を維持（Instruments の Metal System Trace で確認）
- **リサイズ**: 画面回転・キーボード表示でセル数が変わったとき、reflow が壊れない
- **接続**: 回線断 → 復帰で再接続でき、ホスト鍵の変更が検知される

### iPad UI の受け入れ基準

- 小型・大型の iPad の縦横画面、広い・狭いマルチタスクウィンドウ、サイドバーの表示切り替え、連続的なウィンドウのリサイズを確認する。ナビゲーションが変わっても同じセッション ID とシェルを保持する。
- 同じホストへの 2 接続を含む 4 セッションを開き、出力が流れている間にタブを切り替える。各タブが自身の履歴・カーソル・タイトル・接続状態を保持する。1 つのタブを閉じたり再接続したりしても、他のセッションへ影響しない。
- タブ A の資格情報やホスト鍵の確認を **Later** で保留し、B を使ってから A の操作待ちボタンへ戻る。**Cancel** は A の接続試行だけを終了することを確認する。Tailscale サインインでも確認し、切り替え・タブ終了・再接続の途中で遅れて届く認証・貼り付けの結果が、新しい接続試行や別タブに届かないことを確認する。
- 通常・フローティング・外付けキーボードで、日本語変換、タッチ選択、トラックパッドのスクロール、コピー・ペースト、ワークスペースのショートカットを確認する。端末の最終行と IME カーソルが使える位置にあること。
- 複数接続を保持して画面ロック・解除・アプリ復帰を行う。生きているシェルはそのまま再開し、本当に切れた接続だけをタブ単位で表示する。非表示だったことを理由に再接続しない。
- 4 セッションで連続出力と Kitty 画像転送を行って計測する。描画は表示中のターミナルだけで行い、バッファ・キャッシュの上限、入力応答性、メモリ警告時に正常な接続を閉じないことを確認する。
- iPhone の接続、認証、日本語入力、フォント、表示領域のテストも再実行する。カーソルを含む段落の任意の再折り返しは、別途解決するまで上流の既知の制約として扱う。[開発・検証ノート](docs/DEVELOPMENT.jp.md)を参照。

## 10. セキュリティ方針

- 秘密鍵・パスワードは **Keychain** に保存し、生体認証をアクセス条件にする
- ホスト鍵は TOFU で記録し、**変更時はブロッキングな警告**を出す（黙って受け入れない）
- 秘密鍵をアプリ外（クラウド同期・バックアップ）に出さない
- Secure Enclave は P-256 のみ対応のため、`ecdsa-sha2-nistp256` 鍵であれば SE 保管が可能（v1.1 候補、要検証）

## 11. 既知のリスク / 未決事項

| リスク | 影響 | 対処 |
| --- | --- | --- |
| **libghostty-vt の API が未安定**（breaking change 前提で開発中） | エンジン層の書き直しが発生しうる | `TerminalEngine` protocol で隔離し、SwiftTerm エンジンへ退避できる状態を保つ。バージョンを固定して追従タイミングを自分で決める |
| **iOS のバックグラウンド実行制限** | サスペンドで通信が中断したり、サーバーがタイムアウトしたりする | 既存セッションを保持して復帰時に確認し、切断後に再接続を案内する。バックグラウンドでの無期限な接続維持は保証しない |
| **Citadel の対応範囲が未検証** | PTY / window-change / ed25519・ECDSA 鍵 / keyboard-interactive が足りない可能性 | 実装着手前に PoC で確認する。不足分は swift-nio-ssh 層に降りて埋める |
| **Zig クロスビルドの CI 組み込み** | ビルド再現性 | XCFramework の生成を `make` で固定し、成果物をリリースに添付 |
| **Kitty Graphics のメモリ圧** | 大きな画像の連投でメモリ警告 | `ImageStore` に上限とエビクションを持たせる |
| **iPad の複数セッション保持** | 非表示の出力も MainActor を使い、個別の画像・描画キャッシュがメモリを消費する | 初期は 4 タブとし、画像の合計上限を設け、選択中のターミナルだけを描画する。上限を増やす前に連続出力で計測する |
